# Schema

This section describes the database structure and the relationships between collections. The schema consists of master data collections and transactional or operational collections used by the application.

## Database

Collection Name: `users`

| Field | Type | Description |
|---|---|---|
| `_id` | ObjectID | Unique identifier for the user. |
| `username` | String | Username provided by the user during registration. |
| `email` | String | Email address provided by the user during registration. |
| `password` | String | Hashed password used to authenticate the user. Never store the plaintext password. |
| `trimmed_username` | String | Normalized username with leading and trailing whitespace removed, used for consistent username comparisons and uniqueness checks. |
| `trimmed_email` | String | Normalized email address with leading and trailing whitespace removed, used for consistent email comparisons and uniqueness checks. |
| `email_verification` | Object | Contains the email verification token, verification URL, verification status, and timestamps. |
| `email_verification.is_verified` | Boolean | Indicates whether the user's email address has been successfully verified. |
| `email_verification.requested_at` | String | Date and time when email verification was requested, preferably in ISO 8601 format. |
| `email_verification.verified_at` | String | Date and time when the email address was successfully verified, preferably in ISO 8601 format. |
| `email_verification.code` | String | Verification code or token used to verify the user's email address. |
| `email_verification.url` | String | URL containing or referencing the email verification flow. |
| `created_at` | String | Date and time when the user account was created, preferably in ISO 8601 format. |
